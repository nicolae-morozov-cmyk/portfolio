# nicolaemorozov.com — Project Context

## Goal

Rebuild my personal portfolio website, currently hosted on Cargo:

https://nicolaemorozov.com/

The goal is to create a standalone, maintainable website that I fully control and can deploy through GitHub Pages, while preserving the existing visual identity, content, hierarchy, interactions, and overall character.

The intended production URL is:

https://nicolaemorozov.com/

## Source of Truth

The current live Cargo website is the primary reference for:

- content
- page structure
- visual design
- typography
- spacing
- imagery
- interactions
- animations
- responsive behaviour

Screenshots supplied during the project are additional visual references.

Do not redesign the website unless explicitly instructed.

## Technical Direction

Prefer the simplest lightweight static architecture appropriate for a portfolio website and compatible with GitHub Pages.

The site does not require:

- a database
- user accounts
- complex backend functionality
- server-side application logic

Avoid unnecessary frameworks, libraries, and dependencies.

## Working Principles

1. Reconstruct before redesigning.
2. Do not invent content.
3. Preserve the designer's visual intent.
4. Prefer reusable components and clean code.
5. Avoid unnecessary dependencies.
6. Work incrementally.
7. Do not rebuild working sections unnecessarily.
8. Prioritise visual fidelity, performance, accessibility, and maintainability.

## Project Phases

### Phase 01 — Discovery
Analyse the existing website, document the structure and visual system, establish the technical approach, and create `AUDIT.md`.

### Phase 02 — Reconstruction
Recreate the homepage, project pages, navigation, responsive layouts, and meaningful existing interactions/animations.

### Phase 03 — Polish & Deployment
Perform visual QA, test links, optimise media, implement SEO/accessibility/performance improvements, and prepare GitHub Pages deployment.

## Important

Do not begin a later phase unless explicitly instructed.

When a phase asks for analysis before implementation, analyse and document first rather than immediately writing large amounts of code.
